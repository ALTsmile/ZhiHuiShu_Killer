# 智慧树页面结构笔记

这份笔记记录实测到的页面结构，改版时先看这里，再改 `zhskiller/site.py`。

## 一、登录页

- `https://passport.zhihuishu.com/login` 会**纯前端跳转**到
  `https://login.zhihuishu.com/?origin=zhs`，实测需要 **10~16 秒**，
  等太短会一直停在 `Loading ...` 标题上。
- 跳转时页面会经历一次导航，期间执行 `page.evaluate` 可能抛
  `Execution context was destroyed`，所以所有轮询都要包异常。
- 表单元素（在最终页面上，主框架，无 iframe）：
  - 账号：`input[name='mobile']`，placeholder「请输入手机号或用户名」
  - 密码：`input[type='password']`
  - 协议勾选：`input.el-checkbox__original`
  - 提交：`.btn-block__grandient_login`
  - 旧版的 `#lUsername` / `#lPassword` / `.wall-sub-btn` 已经不存在了
- 页面自带网易易盾（`yidun`）与 `captcha.253.com`，滑块随时可能弹出。
- 登录页对短时间刷新有限制：二维码刚出来又被刷新就不会再出现，
  所以**手动登录阶段不能刷新页面**。

## 二、课程播放页（智慧共享课 / `studywisdomh5`）

未登录访问课程播放页时，站点会在十几秒后跳转到
`https://login.zhihuishu.com/?origin=zhs&service=<课程页地址>`，
`service` 参数保证登录成功后自动回到课程页。

前端是 Vite 分块构建，主包 `assets/index-*.js`，目录在 `assets/study-*.js`。
从编译后的模板里读到的真实结构：

```js
// 课时节点（目录项）
class: ["child-info", {
    current: videoId == 当前播放id,
    cur: videoId,
    hasvideo: videoSecShow,        // 有视频才有这个 class
}]

// 完成标记
isStudiedLesson === 1 || (isStudiedLesson === 2 && percentage >= 80)
    ? <icon name="cataCheck" class="child-check" />

// 进度环（Element Plus）
<el-progress class="progress-style" type="circle" :percentage="..." :show-text="false" />
```

**关键结论：`child-check` 在 80% 就会出现，不能拿它当 100% 的判据。**
必须优先读进度环的 `aria-valuenow`，读不到才回退到完成标记。

目录里还有一层「父子小节」：父是 `.child-info`，子是 `.child-info.son`，
两者都带 `hasvideo`。

```html
<div class="transparent-mask"></div>

    <div class="submit-footer">

        <span class="submits">提交作答</span>   <!-- 提交事件绑在这个 span 上 -->
        <!-- 提交后替换成 <span class="done">已提交</span> -->
      </div>
    </div>
  </div>

```

四个必须记住的坑（每个都真实踩过）：

1. **弹窗根既不是 `.el-dialog` 也不是 `.el-overlay`**，而是 `.ai-test-question-wrapper`。
   只按 Element Plus 弹窗找会完全扫不到，表现为「随堂练习永远不自动作答」。
2. **事件绑在里层元素上**：提交绑在 `span.submits`，关闭绑在 `svg.icon-close`。
   点外层的 `.submit-btn` / `.close-box` 不会触发。
3. **`SVGElement` 没有 `.click()` 方法**。用 `el.click()` 点关闭图标会抛
   `TypeError: el.click is not a function`（被 try/except 吞掉后表现为"点了没反应"）。
   必须用 `el.dispatchEvent(new MouseEvent('click', {bubbles: true}))`。
4. **未作答时关闭会被拦下**（i18n `bullet15`：未作答的弹题不能关闭），
   所以流程必须是「每题各选一个 → 提交 → 再关闭」。

另外选项的选中态类是 **`isSelect`**（Vue 对象语法原样输出，不是 `is-select`），
挂在 `span.class-question-select` 上，不在 `.option` 上。

> 播放/暂停来回抖、进度不涨，就是上面第 1~3 条的组合后果：
> 弹窗没被识别 → 程序以为可以播 → 点视频中心 + `play()` → 站点因为弹窗又暂停 →
> 循环往复。手动把弹窗点掉就"恢复正常"，正是这个原因。

## 四、复现这些结论的方法

### 人机验证（网易易盾滑块）的结构与两个坑

实测 DOM：

```html
<div class="yidun_bgimg">                    <!-- 容器 div（不是图片！） -->
  <img class="yidun_bg-img" src="…@2x.jpg">  <!-- 背景图，800x400 的原图显示成 400x200 -->
  <img class="yidun_jigsaw" src="…@2x.png" style="left: 0px;">  <!-- 拼图块 -->
</div>
<div class="yidun_control">                  <!-- 滑轨 -->
  <div class="yidun_slider"></div>           <!-- 滑块按钮（宽 40px，left:0） -->
</div>
<div class="yidun_loadbox">加载中...</div>   <!-- 加载态 -->
<input name="NECaptchaValidate" class="yidun_input">  <!-- 通过后回填票据 -->
```

**坑 1：`img.yidun_bg-img, .yidun_bgimg` 会把容器当图片。**
`.yidun_bgimg` 是容器 div，在 DOM 里排在图片**前面**，用 `.first` 会取到容器；
容器没有 `naturalWidth`，于是抛"验证码元素尺寸读取失败"——
日志里 7 次尝试全部因为这个失败。正确写法是**只取 `img.yidun_bg-img`**。

**坑 2：图片没解码完就量尺寸。**
`naturalWidth` 在图片加载完成前是 0。程序现在会先 `wait_for_function`
等两张图 `complete && naturalWidth > 0`，并且**用下载下来的图片尺寸兜底**，
彻底不依赖 `naturalWidth`。

其它要点：

- 图是 **@2x**（原图 800×400，显示 400×200），模板匹配得到的是原图像素，
  要乘 `显示宽 / 原图宽` 换算成鼠标位移。
- 拼图块初始 `left: 0`，所以位移 = 缺口在背景里的 CSS 位置；
  程序用「缺口位置 − 拼图块当前位置」计算，不依赖这个前提。
- 通过与否除了看弹窗消失，还可以读 `input[name=NECaptchaValidate]` 里的票据。
- 易盾还有"点击/语序"等其它题型，滑块解法不适用，只能交给用户。

## 三·六、章节测验（整页试卷）

从课程目录点「章节测验」后打开的**不是弹窗，而是一整页考试页**。
实测 DOM（由用户复制的页面 HTML 校准）：

```html
<div class="myschool_ewcon">
  <h1 class="titleLength">第四章单元测试</h1>
  <button class="el-button btnStyleXSumit"><span>提交作业</span></button>
  <button class="el-button btnStyleX"><span>暂存作业</span></button>
  <div class="examPaper_box">
    <div class="examPaper_subject">              <!-- 一道题；25 道都在 DOM 里 -->
      <div class="subject_stem">
        <div class="subject_num"><span>1.</span></div>
        <span class="subject_type"><span>【单选题】</span><span>(2分)</span></span>
        <div class="subject_describe">题干…</div>
      </div>
      <div class="subject_node">
        <div class="nodeLab">                     <!-- 一个选项 -->
          <input type="radio|checkbox" value="570802775" style="display:none">
          <img class="flagChecked">                <!-- 每个选项都有，别拿它判断选中 -->
          <span class="ABCase">A.</span>
          <div class="node_detail examquestions-answer"><p>选项正文</p></div>
        </div>
      </div>
    </div>
    <div class="answerCard">…答题卡…</div>
  </div>
</div>
```

四个必须记住的点：

1. **一页一题**：`.examPaper_subject` 共 N 个都在 DOM 里，但只有当前题可见
   （其余被一个 `display:none` 的父 div 包着）。所以必须靠「下一题」或答题卡翻页，
   按可见性逐题作答。
2. **题型**在 `.subject_type` 里：`【单选题】`/`【多选题】`/`【判断题】`。
   判断题是 2 个 `radio`（对/错），多选题是 `checkbox`。
3. **"这题做过没有"只能看隐藏 `input` 的 `:checked`**。
   选项里的 `img.flagChecked` **每个选项都有**（包括未选中的），
   拿 class 里带 "checked" 来判断会把所有题都误判成"已作答"。
4. 提交按钮是 `button.btnStyleXSumit`（文案「提交作业」），点完通常还有确认框；
   `button.btnStyleX`（「暂存作业」）只保存不计分。

### 题干读不到的问题

用户复制的 HTML 里 **`.subject_describe` 是空的**：

```html
<div class="subject_describe dynamic-fonts">
  <div data-v-3d518ffb=""><div data-v-3d518ffb=""></div> <!----></div>
</div>
```

诊断结论：**不是字体混淆（font-face 只有 DINAlternate/priceFont），也没有 shadow DOM**，
那个 div 里就是没有文本节点（`<!---->` 是 Vue 的 v-if 空占位）。
推断是站点异步填充题干，复制时还没填上。

程序的对策：读题干时重试 4 次、每次间隔 0.8 秒；如果仍然为空，
就把 `.subject_describe` 的 outerHTML / innerText / shadowRoot / font-family
打进日志（`exam.diagnose_stem`），方便继续定位。

> 影响：题干读不到时 AI 只能看选项内容猜，单选题准确率会明显下降。

### 在线考试页的地址与保存规则（实测）

章节测验真正的落点是：

```
https://onlineexamh5new.zhihuishu.com/stuExamWeb.html#/webExamList/dohomework/<recruitId>/<token>/<token>
```

页面上的原话：

> 答题后请点【下一题】保存答案，全部试题答完后请点击右上角【提交】按钮完成答题，避免答题记录丢失！

所以：

1. **每题点「下一题」= 保存该题答案**，程序正是这么做的。
2. 全部答完后有两种收尾：
   - 勾了「自动提交」→ 点「提交作业」并处理确认框；
   - 没勾 → 必须先点 **「暂存作业」** 把作答记录存到服务器，
     而且**不能关掉这个标签页**，否则记录会丢（这是早期版本踩的坑）。
3. 新标签页刚打开时会显示 **「正在加载中」**，试卷是异步渲染的。
   必须轮询等 `.examPaper_subject` 出现（程序等 30 秒）再判断结构，
   否则会把正常的测验误判成"没识别到题目结构"，直接跳过去
   （用户看到的现象就是"从第一章跳到第四章"）。

### 保存答案：点「保存」，不要点「暂存作业」

实测（用户确认）：

| 按钮 | 行为 |
| --- | --- |
| 「下一题」 | 保存当前题，翻到下一题 |
| **最后一题时，「下一题」位置会变成「保存」** | **保存全部答案，并且不会关闭标签页** ✅ |
| 「暂存作业」（左上角） | 会弹确认框，**确认后还会把标签页关掉**，答题记录反而丢了 ❌ |
| 「提交作业」（右上角） | 交卷，通常还有确认框 |

所以程序的做法是：每答完一题点一次「下一题」（站点原话就是"答题后请点【下一题】保存答案"），
最后再点一次「保存」把整份卷子落盘；**绝不碰「暂存作业」**。

### 答题卡：用完成率直接跳题

试卷右侧的答题卡里带了完成率和每题状态，不必从第一题一题一题翻：

```html
<h3 class="answerCard_tit percentage_tit"><span>完成率</span><em class="fr"><i>100</i>%</em></h3>
<ul class="answerCard_list1"><li class="green">1</li><li class="green">2</li>…</ul>
```

- `.percentage_tit em i` = 完成率；100% 的测验可以直接略过
- `.answerCard_list li` 每题一个，**已作答的题号带 `green` 类**
- 点某个 `li` 就能直接跳到那一题

坑：新标签页刚打开时答题卡可能**先渲染成"完成率 0%、题号都没状态"**，
这时去判断会误以为整份卷子都没做，于是逐题重答一遍（又慢又白做）。
程序因此要求**连续两次读到相同的完成率**才认为稳定（`exam.wait_card_ready`）。

程序据此：只跳去未作答的题；勾了「复查答题结果」时则遍历全部题目重选。

### 目录里的完成状态

课程目录中的章节测验条目：

```html
<div class="item-test">
  <img src="…/88a8066….png"><span>测试</span>
  <span class="float-right">去完成</span>     <!-- 状态文字 -->
  <img src="…/22d9af1….png">
</div>
```

`<span class="float-right">` 就是状态：`去完成` = 未完成，其它字样（"已完成"/百分比）视为已完成。
注意所有章节测验的名字都叫「测试」，所以程序用「**所属章节 + 名称**」作为条目的稳定标识。

### 章节目录会被收起（随堂练习导致）

实测：课程页的视频在后台播放时，过一会儿会弹随堂练习；**随堂练习一弹出来，
站点就把章节目录收起来**：

```html
<!-- 展开控件（点它就能展开目录） -->
<div class="side-expand-box animated-box show">
  <svg class="svg-icon collapse-btn"><use xlink:href="#icon-collapse"></use></svg>
</div>
<aside class="el-aside a-side">
  <div class="side-wrapper side-wrapper-special">
    <div class="wisdom-category-box hide-box animate-css">   <!-- hide-box = 被收起 -->
      <div class="side-box">…目录…</div>
    </div>
```

目录一收起来，程序就找不到目录项，表现为**卡住不动**。两处应对：

1. `catalog.ensure_visible()`：每次要用目录之前先检查 `.wisdom-category-box`
   有没有 `hide-box`，有就点 `.side-expand-box` 展开；没有目录容器时才退回
   "看目录项可不可见"。（**不要用目录项的 bounding box 判断**：空节点尺寸为 0，
   会被误判成不可见。）
2. 「仅答题」模式下，进入课程页后**主动把后台视频按停**
   （`_pause_background_video`），从源头上避免随堂练习弹出来。

**后续：找到真正的原因了 —— 题干在 closed shadow root 里。**

三次复制的页面 HTML 里，25 道题的 `.subject_describe` **全都是空的**：

```html
<div class="subject_describe dynamic-fonts">
  <div data-v-3d518ffb=""><div data-v-3d518ffb=""></div> <!----></div>
</div>
```

排除掉的可能：不是字体反爬（0 个 PUA 字符、只定义了 DINAlternate/priceFont）、
不是 canvas（0 个）、不是图片题干（176 个 `<img>` 去重只有 6 个 UI 图标）、
`element.shadowRoot` 也是 `null`。

用最小复现验证后确认：**站点把题干渲染进了 `attachShadow({mode:'closed'})`**。
closed 模式下外部拿不到 shadowRoot，`outerHTML` / `innerText` / `textContent`
自然全是空的，但**浏览器的无障碍树能看到渲染内容**：

| 读取方式 | 能否读到 shadow 里的题干 |
| --- | --- |
| `element.outerHTML` | ✗ 空 |
| `element.innerText` / `textContent` | ✗ 空 |
| `element.shadowRoot` | ✗ null（closed） |
| `locator.aria_snapshot()` | ✗ 空 |
| **CDP `Accessibility.getFullAXTree`** | **✓ 能读到** |

所以 `exam.stem_via_accessibility()` 的做法是：

1. `DOM.querySelectorAll('.examPaper_subject')` 按题号定位到那道题；
2. `DOM.querySelector` 找到题内 `.subject_describe`，取 `backendNodeId`；
3. `Accessibility.getFullAXTree()` 取整棵无障碍树，
   按 `backendDOMNodeId` 找到题干节点，再顺着 `childIds` 收集所有文字。

读题干的顺序是 **DOM → 无障碍树**，日志里会写明来源
（`题干取到了（来源：无障碍树 …）`），便于确认走了哪条路。

## 三·五、学习进度是怎么记的（抓包实测）

不要按「视频播到第几秒」去理解智慧树的进度，它是**按观看时长在服务端累计**的：

| 接口 | 作用 | 实测频率 |
| --- | --- | --- |
| `studyservice-api.../gateway/t/v1/learning/saveDatabaseIntervalTimeV2` | 学习时长上报（服务端心跳） | 约每 2~3 分钟一次，外加「随堂练习弹出 / 视频播完 / 切换课时」等事件触发 |
| `studyservice-api.../gateway/t/v1/learning/saveCacheIntervalTimeV2` | 同上，缓存版 | 偶发 |
| `studyservice-api.../gateway/t/v1/cheat/exceptionActionDetail` | 反作弊信息查询 | 页面加载时一次 |

要点：

1. 上报体的业务数据是加密的（`secretStr=...`），响应是
   `{"code":0,"message":"请求成功","data":{"submitSuccess":true}}`。
2. 页面上每 30 秒跳动的百分比是**本地计算**的，服务端值要等下一次心跳才同步。
   所以「进度不动」未必是真的没在记，要看本地百分比有没有涨。
3. **不要为了"跟平台对齐"而把播放位置往回拖**。
   实测两次「开课进度长时间为 0%」都紧跟在一次回退之后，
   而没做过回退的课时 30 秒内就开始计数；怀疑站点把位置倒退当成异常跳转，
   暂停了计时。现在只在"视频播完但进度没满"时才回退补齐。
4. 1.5 倍速下视频一定比计时先结束，必然需要回退补齐一轮左右，
   这是正常现象，不是 bug（`回退到 425s 继续补齐` → 72% → 100%）。

### 章节测验 vs 随堂练习（踩过的坑）

这两者必须严格区分，混在一起会出事故：

| | 随堂练习 | 章节测验（章节练习/章节测试） |
| --- | --- | --- |
| 出现频率 | 每个视频至少 2 次 | 每个章节一次 |
| 是否计分 | 不计分 | **计分** |
| 能不能不答就关 | **不能**（i18n: 未作答的弹题不能关闭） | 可以 |
| DOM 根 | `.ai-test-question-wrapper` | 目前未实测到真实结构 |

**事故复盘**：代码里曾用 `quiz.has_quiz()` 判断"是不是章节测验"，
但那个函数对**任何**题目弹窗都返回 True，于是随堂练习面板被当成了章节测验。
用户没勾选自动完成时会弹窗询问，用户点「跳过」→ 程序去按 Esc / 点取消 →
随堂练习面板**未作答关不掉** → 页面卡住 → 接着切课时又因为目录项
不在视口里而点击超时。现在改成：

1. `quiz.is_chapter_quiz()` 先在文案里匹配
   `章节练习/章节测试/章节测验/单元测试/章节作业/章测试`，
   并且**先排除** `.ai-test-question-wrapper`；
2. 没勾选自动完成时**不弹窗**，只在日志里写一行「已跳过」。

### 目录项的点击

目录是可滚动容器，直接用 Playwright `click()` 常常报
`element is outside of the viewport`（会连等 10 秒再重试，表现就是切课时卡顿）。
`catalog.click_lesson()` 的做法是：先在各级滚动容器里把元素滚到中间，
再用真实鼠标点；实在不行就退回直接派发 `click` 事件。

### 判断"是否已登录"只能用 URL，绝不能用 cookie 名

**真实事故**：早期实现里除了看 URL，还会检查 cookie 名字里有没有
`session` / `jsessionid` / `caslogc` 之类的字样。但实测发现，
站点在**完全未登录**的状态下也会下发这些 cookie：

```
len=32  .zhihuishu.com          o_session_id     ← 名字里带 session，但只是访客会话 id
len=32  passport.zhihuishu.com  JSESSIONID
```

结果就是：用户明明还停在登录页，程序却打印「检测到登录凭证，跳过登录」，
然后自作主张往下跑；紧接着又「课程页要求重新登录」→「检测到登录成功」，
来回打转，用户一脸问号。

**结论**：判断登录状态只看一件事 —— **页面 URL 有没有离开登录域**
（`login.zhihuishu.com` / `passport.zhihuishu.com`）。
智慧树登录成功后一定会自己跳走，这是最可靠的信号。
cookie 只用来做"下次免登录"的恢复，绝不参与判断。

配套的两个保险：

1. `ensure_login()` 会先打开课程页看落点：跳到登录页 ⇒ 需要登录；
   能打开 ⇒ 已登录；既没跳也没识别出目录 ⇒ 按已登录继续（目录问题是另一回事）。
2. `_run_course()` 和 `_run_chapter_tests()` 在识别目录失败时，
   如果当前 URL 是登录页，会**重新走一次手动登录**，而不是直接报错退出。

不需要登录也能做（脚本都在 `tests/`）：

```bat
:: 1. 登录页结构与跳转耗时
.venv\Scripts\python.exe tests\probe_login.py

:: 2. 课程页未登录时跳到哪里
.venv\Scripts\python.exe tests\probe_course.py "<课程播放页链接>"

:: 3. 课程页未登录时的 DOM 概况 + 截图
.venv\Scripts\python.exe tests\probe_course_dom.py "<课程播放页链接>"

:: 4. 下载前端 bundle 并在里面找关键词 / class 名 / 上下文
.venv\Scripts\python.exe tests\probe_bundle.py "<课程播放页链接>"
.venv\Scripts\python.exe tests\probe_chunks.py
.venv\Scripts\python.exe tests\probe_classes.py --file=study
.venv\Scripts\python.exe tests\probe_context.py "--len=2000" "study" "child-check"
```
